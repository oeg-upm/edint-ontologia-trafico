Traffic: Description back to index

This vocabulary represents traffic information for cities, which includes motor vehicles and excludes other types of vehicles or pedestrians.

Therefore, the scope of this vocabulary is defined as follows:

  • Traffic equipment, including traffic measurement devices and those for specific vehicle observations (e.g., speed cameras): measurements they obtain, location of the devices, and road sections they measure.
  • Traffic-related incidents on public roads.
  • Section observed by the device or where the incident occurs.

Figure 1 shows the classes and properties of traffic equipment that perform the measurements.

To represent the equipment, the concept Traffic Equipment has been created, which is related through the property Traffic Equipment Type to a concept in the corresponding taxonomy. It has the following properties: a device identifier dct:identifier, a description dct:description, number of directions of traffic it serves, the number of lanes, and whether it is urban or not (edinttraf:urban).

The device monitors a section, which is a class used to describe both the sections monitored by the devices and the sections of road affected by an Incident. There are two types of traffic equipment: traffic control equipment that performs measurements on specific vehicles and traffic measurement devices. Both, with their corresponding subtypes, are defined in the aforementioned traffic equipment type taxonomy. The class representing traffic devices is itself a subclass of sosa:Sensor of the SSN (Semantic Sensors Network Ontology).

A traffic device observes a traffic property that is a subclass of sosa:ObservableProperty.

Specifically, the traffic measurement device has attributes that indicate whether it is in service or not (inService) and the measurement frequency (measurementFrequency). The class representing traffic measurement properties has several instances that are the defined measurements: intensity, occupancy, load, speed, level, composition, density, and vehicle access. The class traffic observation is a subclass of sosa:Observation, which has a validated property that represents whether the observation has been validated or not. The time at which the observation was made is expressed through the property sosa:phenomenonTime, which links to the class time:TemporalEntity, which represents a time interval or a point in time. Finally, the observation has a feature of interest sosa:hasFeatureOfInterest which is a specific traffic observation point where the observation is made.

Figure 2 shows the classes and properties of traffic incidents.

The main concept in this figure is the incident, which is related to the section through the incident in section property.

Since it is a subclass of geosparql:Feature, it has the property geosparql:hasGeometry that links to its location at a geographic point sf:Point whose attributes are its coordinates. It is also related to the taxonomy of incident types through the property incident type. The edinttraf:Incident has an identifier dct:identifier, a description dct:description, a start date schema:startDate, an end date schema:endDate, the number of directions it affects and the number of lanes. It has two subclasses: planned incident and unplanned incident, for incidents that occurred unexpectedly.

To facilitate understanding the use of some classes and properties in this vocabulary, some examples are provided below:

Traffic Equipment

First, for the representation of traffic equipment, the equipment has an identifier, a description, and, if it is a measuring device, whether it is in service and the measurement frequency. It can also be specified how many directions the device monitors, how many lanes, and whether it is urban or non-urban equipment. It is linked through the traffic equipment type property to the corresponding device type in the traffic equipment type taxonomy, in this case, pneumatic tube.

Traffic Observation

The traffic observation class is related to the "load" property through the sosa:observedProperty property. The validated property indicates whether the data has been validated or not. The sosa:phenomenonTime property, which is related to the time:TemporalEntity class as explained previously, is used to represent the data recording interval.

Incident

To represent an incident, an instance of the Incident class has been created, which has the properties described above: an incident creation date, a start date, an end date, a projected end date, the number of directions, the number of lanes, whether it is recurring, and if so, the reason for the recurrence.
